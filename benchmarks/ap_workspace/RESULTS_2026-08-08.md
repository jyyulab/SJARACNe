# Adaptive-partitioning workspace benchmark: 2026-08-08

## Result

Reusing adaptive-partitioning scratch buffers removed repeated heap allocation
without changing the AP-MI estimator. Against the existing rank-cache
implementation, the representative 100-hub, 5,000-gene, 1,000-observation case
fell from 10.52 to 9.08 seconds, a 1.159x incremental speedup. The 19,936-gene
case fell from 22.29 to 18.39 seconds, a 1.212x speedup.

Across the exact 30-run schedule, summed wall time fell from 191.98 to 160.86
seconds, a 1.193x schedule-weighted speedup. Peak RSS was effectively unchanged.

## Change under test

The baseline allocated four vectors for every candidate pair, three more for
every visited AP partition, one for every split, and a dynamically growing child
vector for every retained quadrant. The candidate creates one workspace per
`createEdgeMatrix()` invocation and reuses those buffers after resetting every
readable range.

This is an allocation-only refactor. It retains the existing `vector<bool>`
quadrant mask, partition equations, thresholds, child order, stack traversal,
and floating-point accumulation order. AP's asymptotic time and memory bounds
remain unchanged; the improvement is a lower constant factor.

## Protocol

- Baseline commit: `e07ea5e`, containing bootstrap-specific rank caching.
- Baseline binary SHA-256:
  `a28c02c7f66c2b7f08b0d10059e0d0aa2126fd512eaa02416e184b1e7d790b4b`.
- Candidate: the workspace-reuse implementation in this commit.
- Candidate binary SHA-256:
  `4c1b980d5e0ddd5d225527869a37cb95b635d473f48726611d4f5c1ed7bf9f08`.
- Arguments: `-S 17 -r 1 -t 100 -e 1`.
- Repetitions: three sequential runs for every case.
- Execution: one SJARACNe process at a time; baseline suite before candidate
  suite; binaries, inputs, and outputs on WSL-native storage under `/tmp`.
- Statistic: median wall time and median maximum resident set size from GNU
  `time`; the schedule sum uses every raw wall-time observation.
- Hardware/software: Intel Core i7-10700F, Ubuntu 24.04 under WSL2, g++ 13.3.0
  with the repository's release flags, GNU time 1.9.

The threshold of 100 is deliberately unreachable and DPI is disabled. AP-MI is
still calculated for every candidate pair while retained-edge serialization and
DPI cannot dominate the timing.

## Correctness and safety

- All 30 candidate timing commands exited zero with empty stderr.
- All 30 candidate adjacency files were byte-identical to their baseline files.
  These timing files are header-only because of the unreachable threshold, so
  this comparison does not establish retained-edge MI equivalence by itself.
- The full Python/native/CWL suite passed: 50 tests, including the five-bootstrap
  acceptance workflow and existing retained-edge legacy MI references.
- A new deep-shallow-deep test verifies that reusing one workspace across pairs
  does not leak partition state. A second test reverses hub order and requires
  identical serialized MI values by edge.
- ASan, LeakSanitizer, and UBSan reported no findings for the focused workspace
  and legacy-MI tests or a 1,000-gene, 500-observation, 100-hub case.

## Scope and limitations

This benchmark isolates rank preparation and AP-MI. It does not measure the
complete production bootstrap schedule, retained-edge-heavy output, DPI, or
consensus construction. The incremental speedups are measurements from one
machine, compiler, seed, and expression matrix, not universal runtime promises.

The baseline suite ran before the candidate suite, so thermal and background
system effects were not randomized. Three repetitions reduce but do not remove
that source of bias.
