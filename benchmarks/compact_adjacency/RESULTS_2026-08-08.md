# Compact sorted-adjacency results (2026-08-08)

## Outcome

Replacing each `std::map<int, Node>` adjacency row with a compact,
target-sorted vector substantially reduced memory and improved traversal time.
The most operationally relevant result was the full BRCA100 seed-1 run:

- median peak RSS fell from 493,760 KiB (482.2 MiB) to 252,160 KiB
  (246.3 MiB), a **48.9% reduction**;
- median wall time fell from 226.70 s to 217.91 s, a **1.04x speedup**;
- the coarse internal DPI time fell from a median of 18 s to 11 s, a
  **1.64x DPI-phase speedup**; and
- every retained network data row was byte-identical between implementations.

The smaller total-runtime gain is expected. AP-MI remained the dominant phase
and was not changed by this optimization; the adjacency representation mostly
affects graph construction, DPI, and output traversal.

## Implementation being measured

The candidate stores each edge as one contiguous record containing MI, target
gene ID, and DPI intermediate ID. Rows remain sorted by target ID.

- MI-generated rows use amortized constant-time append because targets are
  visited in ascending ID order.
- Imported adjacency rows append in file order, stable-sort once if needed,
  then deduplicate in place. The last retained duplicate remains authoritative,
  matching the legacy map update.
- Edge lookup uses binary search, retaining `O(log d)` lookup for row degree
  `d`.
- Iteration remains `O(d)`, but edges are contiguous instead of separately
  allocated tree nodes.
- Row capacities are compacted before DPI, so unused vector capacity is not
  carried alongside the reverse-neighbor index.

Both representations use `O(G + E)` graph memory asymptotically. The gain is a
large constant-factor reduction: the vector record is 16 bytes on this tested
64-bit build, while a tree node additionally carries multiple pointers,
balancing metadata, and allocator overhead.

## Matched results

Values are medians of three measured runs per implementation. Replay cases had
one warmup per implementation; the expensive full BRCA case had no warmup.
Runs were serial and baseline/candidate order alternated.

| Case | Directed edges | Map wall (s) | Vector wall (s) | Speedup | Map RSS (MiB) | Vector RSS (MiB) | RSS reduction |
|---|---:|---:|---:|---:|---:|---:|---:|
| Selected hubs H=10, T=4,000 | 40,040 | 0.100 | 0.094 | 1.06x | 18.9 | 16.8 | 10.6% |
| Selected hubs H=50, T=4,000 | 200,200 | 0.238 | 0.193 | 1.23x | 31.3 | 22.1 | 29.5% |
| Selected hubs H=100, T=4,000 | 400,400 | 0.437 | 0.337 | 1.30x | 47.5 | 29.0 | 38.9% |

The dense control did not regress. The largest synthetic speedup occurred on
the degree-skewed all-gene graph, where contiguous traversal and smaller rows
matter most.

## BRCA phase interpretation

The full expression matrix contains 28,278 genes and 100 observations, and all
2,608 requested TF hubs resolved. Across the three full runs:

- the map implementation reported MI/construction times of 207, 207, and 207 s
  and DPI times of 18, 19, and 18 s;
- the vector implementation reported MI/construction times of 205, 209, and
  206 s and DPI times of 11, 11, and 11 s.

These internal timers use whole seconds, so high-resolution GNU user and wall
times in the CSV files are the primary measurements. The phase logs support the
same conclusion: MI was essentially unchanged, while DPI became faster.

The BRCA adjacency replay uses the stored `TF_run.adj`, which is already
thresholded and DPI-pruned. It is a valid real-topology loading/traversal/RSS
benchmark, but it is not a faithful replay of first-pass DPI on the denser
pre-DPI graph. The full seed-1 run is the end-to-end result.
