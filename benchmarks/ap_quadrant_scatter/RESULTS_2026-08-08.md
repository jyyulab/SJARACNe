# Stable quadrant-scatter benchmark: 2026-08-08

## Result

Replacing the adaptive-partitioning quadrant mask and repeated child scans with
one stable counting scatter produced a substantial incremental gain over commit
`54ca6a3`, which already reused AP scratch memory.

For the representative 100-hub, 5,000-gene, 1,000-observation case, median wall
time fell from 11.21 to 4.11 seconds: **2.731x faster** and 63.39% less runtime.
The 19,936-gene case fell from 22.75 to 8.54 seconds: **2.664x faster**.

Across the exact 60-run schedule, summed wall time fell from 202.53 to 83.74
seconds, a 2.419x schedule-weighted speedup. This aggregate is useful for
reproducing this schedule, not as a universal end-to-end speedup.

## Change under test

The baseline classified each observation into a four-way quadrant using a
`vector<bool>` one-hot mask. For every recursive quadrant it then rescanned the
entire parent partition, appended matching observations to a child vector, and
copied that child vector back into the AP ordering buffer.

The candidate stores one byte-sized quadrant ID per observation. For an accepted
split, it computes packed offsets only for recursive children (`NN > 2`) and
scans the parent once, writing each eligible observation directly into its final
child block. The scatter is stable: child blocks remain in quadrant order and
observations retain their order within each child.

The AP equations, split threshold, leaf threshold, stack order, leaf
contribution order, and floating-point operations are unchanged. Complexity
remains linear in the number of observations visited by a partition because
there are only four quadrants; this is a constant-factor improvement. Workspace
storage is also reduced by roughly `3.5 * N` bytes by replacing the 4N-bit mask
and N-integer child buffer with N byte-sized quadrant IDs.

## Protocol

- Baseline commit: `54ca6a3`, containing rank caching and reusable AP buffers.
- Baseline binary SHA-256:
  `b2491fa6b569cea0e6963f622ead3b197d79bf946f946c3645849722321003e7`.
- Candidate: the stable quadrant-scatter implementation in this commit.
- Candidate source SHA-256: `matrix.cpp`
  `c6e282ff1281219bfb6f0bc097cd51df9577a2b3ce50d007dcb5e4e5aa86c10d`;
  `matrix.h`
  `79009f85972f363d5bb2c2e4a8e54cdf40f7b0909ee127bbee297731fd747cee`.
- Candidate binary SHA-256:
  `6f350fd8dd22548fb6622d41b543d5e96bf515b1e3542d138b4842e9e8946918`.
- Compiler: Microsoft C/C++ 19.44.35226 for x64, `/std:c++14 /O2 /EHsc`.
- Arguments: `-S 17 -r 1 -t 100 -e 1`.
- Repetitions: three per case, after an unrecorded warm-up for each binary.
- Execution: one process at a time on the Windows host. Within each case,
  repetitions used baseline/candidate, candidate/baseline, then
  baseline/candidate order.
- Timing: `System.Diagnostics.Stopwatch` around a directly managed child
  process; stdout and stderr were redirected to per-run files.
- Statistic: median wall time. The schedule sum uses all raw wall-time records.
- Hardware: Intel Core i7-10700F.

The threshold of 100 is deliberately unreachable and DPI is disabled. AP-MI is
still calculated for every candidate pair while retained-edge serialization and
DPI cannot dominate the timing.

## Correctness and safety

- All 60 timing commands exited zero with empty stderr.
- Every candidate timing adjacency was byte-identical to its matched baseline.
  These files are header-only because of the unreachable threshold, so this
  check alone does not prove retained MI equivalence.
- A separate `-t 0` run with 100 hubs, 1,000 genes, and 500 observations retained
  96,699 edges. Baseline and candidate files were byte-identical, with SHA-256
  `5f7fbe8baf49ccc7cc4bb992e01b196a88e0af97d677d5466d0bb768c53a6f4a`.
- A new 4/2/2/4 quadrant fixture retains the legacy MI `0.056633`; it tests
  recursive-child packing when 1-2-point leaf quadrants lie between children.
- The 29 focused platform-independent tests passed against the candidate binary.
- MSVC AddressSanitizer reported no findings in the three AP workspace/scatter
  tests or the 1,000-gene, 500-observation, 100-hub stress case.

A full Windows discovery run reached 45 passes, two Linux/glibc-specific skips,
and four environment/platform errors unrelated to this C++ change: three
line-ending tests rely on POSIX temporary-file semantics, and the acceptance test
expects the Unix `sjaracne` launcher. The complete WSL suite and Linux
ASan/UBSan were not rerun because WSL execution was unavailable during this run.

## Scope and limitations

This is a matched Windows/MSVC benchmark. The optimization removes work on every
platform, but the measured 2.4-2.7x multi-hub gains must not be presented as
confirmed Linux/WSL or end-to-end workflow speedups until they are measured
there. The benchmark isolates rank preparation and AP-MI; it does not measure a
production bootstrap schedule, retained-edge-heavy output, DPI, or consensus.
